What Bonsai 2 27B is

PrismML's newest model, released 17 Sep 2026. It is a squeezed-down copy of Qwen3.8-27B, a model about 3× the size of the one the 8B came from. Like the 8B, it stores every weight as −1, 0 or +1. That shrinks it from 54 GB to 7.2 GB and keeps 98.2% of the full-size model's test scores. It can also look at pictures and handle conversations 4× longer.

Inside: why 3× bigger isn't 3× hungrier

Each block below is one layer, a step the text passes through. More layers and more weights hold more knowledge but take longer. The difference is how the layers remember the conversation.

Ternary Bonsai 8B36 layers; every one looks back over the whole conversation
Bonsai 2 27B64 layers; only 1 in 4 looks back over everything
Looks back over every earlier token, so it needs memory for each one ("full attention") Keeps a fixed-size running summary instead ("linear attention")

Memory to hold a 32,000-token conversation (GB)

Only 16 of the 27B's layers need room per token, and each needs less. The result: 35 KB per token against the 8B's 78 KB. So the bigger model holds a long conversation in half the memory. Its limit is 262,144 tokens against the 8B's 65,536; on your Mac, about 90,000 would fit (est.).

How both squeeze their weights

Normal model, 16 bits each:
0.0132 · −0.0207 · 0.0009 · 0.0188 · −0.0151 …
Bonsai, about 2 bits each:
+1 · −1 · 0 · +1 · −1 … × 0.017

Made-up numbers to show the idea. Each weight becomes −1, 0 or +1, and every 128 weights share one scale (the × 0.017). This is how 16.4 GB becomes 2.18 GB, and 53.8 GB becomes 7.21 GB.

What it would mean for Bonsai Code

PartWith the 27BWhy

Bottom line. On paper the 27B is clearly the better coder. Writing correct code from a focused job is exactly what the round 2 fix and feature paths ask of it. The cost is time: every try takes about 4× as long on this Mac, and the tool-calling score barely moves. The only way to know if the trade is worth it is to run the same 15 practice tasks on it. The app already has a spot for the 27B in its model list.

Where the numbers come from

  • 27B model page (sizes, speeds, 14 scores, settings): huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf. Also its known-issues list: KNOWN_ISSUES.md
  • PrismML's announcement, 17 Sep 2026: prismml.com/news/bonsai-2-27b. It uses a wider set of tests (overall 83.9); this page uses the model page's 14 tests (84.78).
  • 8B model page (scores, M4 Pro speeds): huggingface.co/prism-ml/Ternary-Bonsai-8B-gguf
  • The 27B file's own header, read directly: 64 layers, 1 in 4 full attention, each with 4 memory heads of 256. Memory per token is worked out from that, with the same 8-bit memory setting Bonsai Code uses.
  • Your Mac: the 8B speeds and memory are from round 1 (bonsai-code-built.html). The 11.5 GB graphics-memory limit was read from macOS.
  • How the 27B estimates were made: writing = 8B's speed here × (18.0 ÷ 76) and reading = 233 × (125 ÷ 455). Those ratios are PrismML's M4 Pro numbers for the 27B ÷ the 8B. Memory = the 7.21 GB file + 1.30 GB conversation memory + about 0.5 GB of working space.
