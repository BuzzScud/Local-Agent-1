Models often read files through Bash (cat, head, grep -rn, ls, find) instead of this harness's own Read, Search and List tools, so long files come back whole and nothing counts as a read. Change the harness so that a plain read in a Bash call runs as the matching tool instead. Export plainRead(command, cwd) from tools.mjs: it returns { name, args } for the tool a command stands for, or null when it is not a plain read. The commands and what they stand for: cat FILE is Read FILE; head -n N FILE or head -N FILE is Read FILE from line 1, N lines (head with no count: 10 lines); tail -n N FILE or tail -N FILE is Read FILE's last N lines (with the right offset, a file that ends in a newline included); sed -n 'A,Bp' FILE is Read FILE lines A to B; grep -r, -rn or -nr PATTERN DIR (the pattern quoted or not; DIR may be left out) is Search PATTERN in DIR; ls DIR (also ls -la DIR, or ls alone for the folder) is List DIR; find DIR -name GLOB (optionally with -type f) is List DIR with pattern **/GLOB. Anything else runs as typed: a pipe, a redirect, ; or &&, $( ), a flag the tool has no word for (head -c, grep -i), two files, or a path that does not exist. In agent.mjs, step runs a Bash call that plainRead maps as that tool, and its text then starts with "(Run as Read)", "(Run as Search)" or "(Run as List)" on a line of its own, followed by the tool's own text. Keep the existing tests passing and add tests for the new behaviour.
