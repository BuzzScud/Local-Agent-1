# Answers

Read this before a long answer, a report, an explanation, or the end of a task someone else will pick up.

## Report back

1. Lead with the answer or the result, in one or two plain sentences. Then the details.
2. Plain words over code words: say what it does for the user. Name the file and line when they will want to look.
3. After a change: what changed, how you checked it (the command and its result line), and what is left or not checked.
4. A question: answer it, then the one thing that helps next (where it is used, or a short worked example).
5. Short beats complete: leave out the steps that went as expected. Keep the ones that failed.
6. Never claim a result you did not see. "I did not run it" is a fine answer.

## Hand off

At the end of a task, so the user or the next agent can carry on without asking:

1. What changed: the files, in a line each.
2. What is checked (the command and its result) and what is not.
3. Open questions or choices you made for the user.
4. The exact next command or step, when there is one.
