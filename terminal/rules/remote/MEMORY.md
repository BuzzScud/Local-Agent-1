# Memory

Read this when the user asks you to remember something, or when you learn something that
will matter in later conversations.

## What is worth keeping

1. Keep what is not in the code and will matter next time: a preference of the user, how this project is run or deployed, a decision and its reason, a trap that cost time.
2. Do not keep what the code, git history or AGENTS.md already says, or what only matters to this conversation.
3. One fact a line, in plain words, with the date when it can go stale ("on 2 Oct the service at … was down").
4. A remembered fact can be out of date: before you act on one that names a file, a command or a setting, check it still exists.
5. When the memory and what you see disagree, trust what you see and say so.
