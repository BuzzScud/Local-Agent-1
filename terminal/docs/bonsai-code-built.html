What's in it

  • Claude Code's flow: welcome box, ⏺ Tool(arg) / ⎿ result lines, red/green diffs, a plan list, the spinner, the input box.
  • Asks before every edit and command: Yes · Yes for this session · No and say what instead.
  • Always blocked: rm -rf, sudo, git push, git reset --hard, kill/pkill, stopping services.
  • Starts and stops the model itself; restarts it if it crashes.
  • Saves every conversation: bonsai -c or /resume.
  • Built for a small model: forgiving tools, loop and repeat guards, a thinking budget, memory trimming.

Honest limits

  • The 8B is the weak link. On its own it finished 5 of 15 practice attempts: it is good at finding things and answering questions about code, shaky at renames, and it did not finish any multi-step edit task. Treat it as a fast local helper, not as a replacement for Claude on real work.
  • Its most common failure is misunderstanding what to change. The tools stop it from damaging files (an edit that breaks a file that worked is refused, and the file is left as it was), but they cannot make it understand the task. Keep 'ask first' on and read the diffs before saying yes.
  • Thinking mode is about 10× slower per task here and did not score better, so it is off by default.
  • Switching layout (ctrl+l) changes how new lines look; lines already printed stay as they are, because a terminal can't redraw its history.
  • Memory: about 4.8 GB while it runs at 32k; with less free it drops to 16k and says so. The disk is 92% full; the model and runtime use 2.3 GB of it.
