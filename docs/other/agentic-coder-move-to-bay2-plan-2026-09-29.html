Day to day The first question after a model starts waits about 20 s longer. After that it answers at the same speed, because the model runs from memory, not from the drive.
The slow part is writing BAY2 writes at 31 MB/s, about a USB stick's speed. Big writes (warm caches, app rebuilds, the first copy) are where you'll feel it. Option C on tab 6 keeps the warm caches on the Mac.
The drive itself USB, 60 GB, APFS. It tells “Foo” and “foo” apart, unlike the Mac. Programs can run from it: it's mounted without a block on running them (checked).

What changes, and what doesn't

Same Works as today

  • Every path you and the scripts use: ~/.agentic-coder, ~/Desktop/agentic-coder, ~/worktrees/…. The shortcuts lead to the drive.
  • The command fence, tested on BAY2 today: commands can write inside a project there, other folders on BAY2 stay blocked, and bun and git run.
  • The trusted-folder list follows shortcuts, so the repo stays trusted.
  • The 9 worktrees whose node_modules point at the repo, and ~/.agentic/memory, which points at memory-about-you.
  • Starting coding from your home folder (42 of your 46 recent starts).

Changes With BAY2 plugged in

  • When started inside the repo or a worktree, the app sees the real path /Volumes/BAY2/…. So it:
    • skips your home AGENTS.md, because it only looks upward from the real path
    • doesn't list that folder's older sessions (there is 1)
    • asks once to trust each worktree
    Option A on tab 6 fixes all three.
  • Time Machine backs up both folders today, to drive “1”. It skips BAY2, so your sessions, the test record and memory-about-you would have only one copy. See option B.
  • git is told the drive is case-sensitive (step 9).

Stops With BAY2 out

  • coding, coding hub and the Agentic Coder app. coding says why.
  • Every page in cli docs, including gemma-docs, morning briefs and memory-about-you (Agentic Coder's memory about you).
  • /repo-morning can't save its brief there.
  • Claude and Codex sessions working in those folders. Sessions that start from your home folder still start.
  • Nothing else on the Mac uses these folders. No scheduled job points at them (checked).

Undo: about a minute
  1. Remove the shortcuts.
  2. Move the old copies back (instant, same disk).
  3. Remove the drive check from coding.

Nothing on BAY2 has to be deleted to undo it. If you've worked on the drive since, those changes get copied back first.

While it runs Agentic Coder is off for about 30–40 minutes. Other projects (Orbit, MAIN2026, the Ladder) aren't touched.

Your call: four extras, then the go-ahead

The plan on tabs 1–5 works without any of these. I'll ask about them in one question after you've read this.

Option A
The app uses the path you typed

When the folder you start in (~/Desktop/agentic-coder) is the same folder as the real /Volumes/BAY2/…, the app keeps the name you used. That fixes all three items under “Changes”: the home AGENTS.md, the older sessions and the trust prompts.

Cost: about 10 lines in terminal/src/cli.jsx plus a test. It goes to the public repo only when you say commit.
Option B
Time Machine backs up BAY2 too

External drives are left out of Time Machine by default. Taking BAY2 off that list keeps a second copy of your sessions, memory and test record, as there is today.

Cost: one setting you change yourself (System Settings → Time Machine → Options), or a command that needs your password. The first backup copies ~16 GB to drive “1”.
Option C
Keep the warm caches on the Mac

The slots folder (0.6 GB) is what gets written most. Keeping it on the Mac avoids the ~3 s per save.

Cost: one shortcut pointing back to the Mac. That 0.6 GB stays on the Mac, and it's only a cache.
Option D
Also move the engine sources

prism-llama.cpp (1.0 GB) and mlxfast (67 MB) are the sources the model engine was built from. The built engine already moves with app-data.

Cost: +1.1 GB on BAY2. Rebuilding the engine would then need the drive too.
