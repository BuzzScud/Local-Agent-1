What the amber ones have in common

The bar. The app only hands code over when the best match scores at least 0.58. Three questions scored 0.55–0.56, so Gemma got nothing, even though in one of them the right function was 3rd.

Test and practice code. In 4 of the 10 misses in this repo, the top result was a test, a practice project or a report script, not the app's own code. One answer was found only 18th, behind a copy of it in the test bench.

Missing context. A function carries only its own name and file. Once, the file's opening comment (which says what the file is for) beat the function it describes.

Searching by meaning takes about 30 thousandths of a second, so every fix here can be generous with how much it looks at.

Step 1: a card for every file, full detail where the question lands

Today the search reads full detail for the ~100–260 files it has room for, and nothing at all for the rest. The idea: a two-line card for every file, so any file can be found, and full detail only for the files a question actually needs.

Steps 2–4: search better within the files it reads

These aim at the 10 misses in this repo, where the right file was read but the answer did not reach Gemma.

2 · App code first, with its context
  1. Code in test folders, practice projects and report scripts scores a little lower, so it wins only when it is clearly closer.
  2. Each piece the search reads starts with its file's opening comment (a line or two on what the file is for), not only the file's name.
  3. The index is rebuilt once. The model is still handed the same code.

Anthropic published the second idea, adding a piece's context before indexing it, and reported about a third fewer misses. It wrote that context with a large model; this uses the comment already in the file, at no cost. Done when: handed 15 → 18 or more in this repo.

3 · Set the bar with evidence

Three questions scored 0.55–0.56 against a 0.58 bar and got nothing. When the bar was set, questions about nothing in the project scored up to 0.54, so lowering it blindly would hand Gemma unrelated code. First add 10 questions that should bring nothing, then move the bar only as far as those allow.

4 · Try a search model made for code

Today's model, BGE-M3, learned mostly from ordinary writing. Qwen3-Embedding 0.6B is the same size and learned from code too. It gets one run on the same 50 questions and is kept only if it wins by 3 or more. It is a download and a comparison. Nothing changes if it loses.
