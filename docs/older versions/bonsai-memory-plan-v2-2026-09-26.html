A memory that makes Bonsai better each time you use it

Today Bonsai forgets everything when you close the window, unless you type "update memory". This plan makes it save what it learns on its own, keep it tidy, and bring back only the facts that fit the request in front of it.

How it works

Four steps. The first two happen after a task, the last two before the next one.

1 · After a task
Collect

Bonsai gathers what happened: your request, your corrections, what it changed, which tries passed or failed, and whether it got stuck.

2 · In the background
Save

The model turns that into at most 5 short facts. If you send a new request, the save steps aside and finishes later.

3 · On disk
Store

Each fact is its own small file with its kind, its key words, and where it came from. The index gets one line per fact.

4 · Next request
Recall

The request's words narrow the facts to about 10. Julia 1 picks the ones that fit, most trusted first. They travel with the request. The 27B is not needed for this.

Why the facts travel with the request: Bonsai saves the model's reading of its fixed instructions to disk, so a start takes a fraction of a second. If memory sat inside those instructions, every new fact would throw that saved reading away. Placed after them, memory costs nothing at start.

What the index is

An index is like the table of contents of a book: a short list with one line for each saved fact.

The indexA fact
What it isOne short line per factThe full note, with where it came from
When Bonsai reads itAlways, at every startOnly when your request matches it
WhySo Bonsai knows what it knowsSo it does not read 200 facts to use 2
SizeKept short: the most trusted and most used lines firstNo fixed limit on how many there are

Without an index Bonsai has to load everything it ever saved. That is what it does today, and why it stops at 6,000 characters.

What it learns

Four kinds of fact. Each one comes from something Bonsai can see for itself, not from a guess.

How you like to work

Saved in your own memory, used in every project.

"Explain what you are going to do in plain language before doing it."
Comes from: what you say, and the corrections you give after an answer.

Project facts

Saved in the project's memory.

"The rules for fixing bugs are in terminal/rules/bug-fixing.md."
Comes from: files it read and commands that ran without error.

What worked and what failed

Saved in the project's memory, with the check that proved it.

"Failed: raising the menu's z-index. Worked: lowering the legend's."
Comes from: the result of each try and of the project's tests.

Its own mistakes

Saved in your own memory when it is about how Bonsai works, in the project's when it is about the code.

"Read the same file four times and stopped. Next time: ask, do not re-read."
Comes from: a loop, a stop at the time limit, or you pressing esc.

Trust: how a fact proves itself

This is the part that makes the memory smarter over time, and not only fuller.

What happened after the fact was usedTrust
The task passed its checkGoes up by 1
The task failed, or Bonsai got stuckGoes down by 1
You corrected Bonsai or pressed escGoes down by 2
You saved or pinned the fact yourselfNever drops below where you put it
Trust falls to minus 3The fact retires, with the reason in the log. Undo brings it back.

A task that fails is not always the fact's fault, so one failure never retires a fact. The numbers above are a starting point and are tuned by the checks.

The four extras

Start with what is already written

The first time Bonsai is used in a project, it reads the project's AGENTS.md, its past Bonsai sessions and its runs in the test record, and saves facts from them.

Runs once per project, in the background. Facts from it start with trust 0 until a task proves them.

Recipes for repeated jobs

When the same kind of job is done a second time, the steps that worked are saved in order. The third time, the recipe comes back with the request.

"Add a page: 1 build it, 2 save it in the DOCS folder, 3 run bun run docs, 4 commit."

Review at night

While the Mac is idle, Bonsai re-reads the day's sessions, finds lessons the quick saves missed, and tidies.

It never wakes the Mac, runs only on power, waits when a test run has the model, and stops the moment you start Bonsai.

Memory tab in the hub

A page in the browser with every fact: its kind, trust, how often it was used, and where it came from. You can edit, pin, retire and restore.

Next to the Tests tab. /memory opens it.

Keeping it clean

Every change is one line in a log. /memory shows what is saved and what changed last; /memory undo takes back the last change.

Build steps

In this order. Each step is tested before the next starts, and the 247 existing tests must keep passing.

  1. Test Julia 1

    Download it, run it on your Mac through a small helper program, and measure speed, memory and how often it picks the right fact, next to word matching on the same 30 requests.

    Files: new models/julia-1/, a runner under models/evals/. Decides whether step 4 is built.
  2. The store

    Facts as small files with their trust, the index, the retired folder and the log. Your two rules go in as the first facts. An existing notes file is carried over line by line.

    Files: terminal/src/agent/memory.mjs, new tests. No model needed.
  3. Recall by words

    The index is placed after the fixed instructions. Matching facts go with the request, the way bug steps and your math notes already do. The 27B writes related words when it saves.

    Files: agent/prompt.mjs, agent/agent.mjs.
  4. Julia 1 picks

    Only if step 1 passed. Julia 1 runs beside the 27B and picks among the facts the words found. If it is not running, recall falls back to words alone.

    Files: models/runtime/, models/index.mjs, agent/agent.mjs.
  5. Saving on its own

    A save starts when a task ends and when you quit. It runs on the model's second slot, steps aside when you type, and finishes after the window closes.

    Files: agent/agent.mjs, app/App.jsx, headless.mjs. Here the real save time is measured.
  6. Learning from results, and trust

    Each task leaves a short record: tries passed and failed, your corrections, loops, interruptions. The save reads it, and the facts that were used gain or lose trust.

    Files: agent/agent.mjs, agent/memory.mjs, flows/.
  7. Start with what is already written

    The first-use reading of AGENTS.md, past sessions and the test record.

    Files: agent/memory.mjs, app/store.mjs, the test record through models/index.mjs.
  8. Recipes

    Spot a repeated kind of job, save its steps, recall them.

    Files: agent/memory.mjs, agent/agent.mjs.
  9. Upkeep, undo and /memory

    Merge, replace, retire, the log, and the command with undo. The Help page gets the new command.

    Files: agent/memory.mjs, app/commands.mjs, app/App.jsx, app/help.mjs.
  10. Memory tab in the hub

    The page, its data, and edit, pin, retire and restore.

    Files: new app/memory.html, app/hub.html, app/weights.mjs.
  11. Night review, then measure

    The review that runs while the Mac is idle. Then all eight checks on the real model, written to the test record, with a results page in the DOCS folder.

    Files: models/evals/bench/, reached through terminal/index.mjs.

Limits you should know

  • The model does not grow. A harder problem than the model can solve stays too hard. Memory saves it from repeating work and repeating mistakes.
  • The gain shows in projects you return to. In a folder opened once, there is nothing to remember yet.
  • A small model can save a poor fact. That is why each save is limited to 5 facts, each must name where it came from, and the last check reads them.
  • Only one model fits in memory on this Mac. A save shares the model with your next request, which is why it steps aside when you type.
  • Julia 1 is one day old. It may not beat word matching here. The plan works without it.
  • Two models share 16 GB. If memory runs short with the 27B at its largest setting, Julia 1 is the one that stops.
  • A wrong fact can mislead. Facts about code are checked against the files before they are recalled. Facts about you are only replaced by what you say later.

Small picks I made for you

You did not have to decide these. Say so if you want any of them different.

  • Your own memory lives in ~/.bonsai/memory/, a project's in .bonsai/memory/ inside the project.
  • A save may finish after the window closes. The model already stays loaded for a while after you quit.
  • The night review starts after the Mac has been idle for 30 minutes, between 1 AM and 6 AM, and only on power.
  • Julia 1 does one job now, picking facts. Its other possible jobs wait until that one is proven.
  • The old "update memory" words keep working and save at once.
  • A setting turns saving on its own off, for a project or everywhere.

Words

Fact
One short thing worth remembering, in its own file.
Index
A short list with one line per fact. It is the only part of memory always loaded.
Recall
Bringing a saved fact back for a request that matches it.
Retire
Move a fact out of use without deleting it, so it can be brought back.
Recipe
The steps that worked for a job you repeat, saved in order.
Trust
A number on each fact that goes up when it helped and down when it did not.
Decision model
A small model that picks among choices you give it. It does not write text.
Slot
A place in the model server for one conversation. Bonsai has two: one for you, one for side work such as a save.
Token
A piece of a word. The model reads and writes in tokens.
