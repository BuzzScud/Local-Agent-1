What happened to you: the form opens on Run on. ↑ from there jumps to the last row, Save only, and enter saved the service without connecting.

Why it reads wrong

  • “Another service saved” sounds like something else is using the model. “Another service” is only the name of the Run on choice.
  • “This window stays on this Mac” means server-1 in your jumped window, but reads as your own Mac.
  • enter never just connects: on a text row it starts editing, on Run on it moves down a row, so Connect is two or more presses away.
  • After Save only nothing offers to connect. The only way is /remote service, which the line mentions at the very end.

Both designs fix all four: enter connects from any row, ↑ from the top lands on Connect, the lines name server-1, and Save only offers to connect.

Design 1the same form, tidied: Connect and Save only share one row, and Save only asks the way the app's other questions do (drawn on the app's grid, colours from the capture)

What changes

  • enter connects from any row. Typing on Address, API key or Model changes it, as today.
  • One button row at the bottom: [ Connect ] Save only. ←→ pick, ↑ from Run on lands here on Connect, s saves only from any row.
  • The title says where the window runs now: server-1 · its own model is off.
  • Save only closes the form and asks in the app's question box: 1. Connect now (recommended) · 2. Not now.
