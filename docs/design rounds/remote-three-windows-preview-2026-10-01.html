All three windows use one service, so sometimes it answers "too many requests, slow down". This is what one window shows when that happens.

How long it waitsAs long as the service asks (here 20 s), and a little longer on each try.
All windows wait togetherWhen one window hears "busy", the others pause too, so they don't all knock again at once.
If it stays busyAfter 5 tries (about 3 minutes) it stops and says so. Your conversation is kept; ↑ then enter tries again.
What changes nothingA real "too long" message still shrinks the conversation as before. Only "busy" waits.

Window 1 is changing the project. You open window 2 in the same folder. (Both Today screens were taken at the same moment.)

Your /remote choice is saved for every window. That is right for new windows. It is wrong for one thing: the memory save a window does after you close it.

Today
  1. Window 1 connects to OpenRouter.
  2. In window 2 you pick Ollama with /remote. That choice is saved for every window.
  3. Window 3 opens on Ollama: the last one you picked. fine
  4. You close window 1. It writes its memory notes after closing, and connects again to do it: to Ollama, not OpenRouter. wrong

Checked in the code: the after-close save reads the saved choice at that moment, not the window's own.

New
  1. Window 1 connects to OpenRouter.
  2. In window 2 you pick Ollama. Saved for new windows, as today.
  3. Window 3 opens on Ollama. same
  4. You close window 1. Its memory save goes to OpenRouter, the service it used. fixed

Each window remembers the service it connected with, and uses only that one until it closes.
