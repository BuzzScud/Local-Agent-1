Loops

1 · Tree drawn like your /agents screen

  • This window on top, a box per loop under it, a log of what they said at the bottom.
  • Each box shows the loop’s four steps as bars, with the step its run is on lit, and the way back to the first step.
  • Good at: how the loops are set up and where every one of them is, in one picture.
  • Weaker at: a run’s own lines are one key away (enter), and past four loops it moves sideways.

2 · Feed one stream of what happened, in order

  • Everything the loops did, oldest to newest, like a chat: each finished run with its result, each question, each note you sent.
  • Runs under way are at the bottom, with the lines they are writing. The loops are listed on the left, and the picked one is marked in the stream.
  • Good at: catching up after you were away, and seeing your notes next to what the loops did with them.
  • Weaker at: with many loops that run often, the stream moves fast.

3 · Focus one loop full size, the others as tabs

  • The picked loop looks like a conversation in the app: your message, its steps, its answer. The other loops are tabs along the top, each with its state.
  • Beside it: how one run goes, with the step it is on, and the loop’s past runs.
  • Good at: working closely with one loop and steering it.
  • Weaker at: the other loops are one line each.

4 · Timeline + diagram a rail per loop, the run drawn as boxes

  • Each loop is a rail in time: a dot where a run starts, a thick line while it runs, ✓ or ✗ where it ends, ◇ where the next ones are due.
  • Under it, the picked loop’s run as a diagram: four boxes with arrows, the step it is on lit, and the arrow back to the start.
  • ← → walk the runs. [ ] change the time scale.
  • Good at: when things ran, and where a run is right now. Weaker at: it wants the full width.

Try this about two minutes

  1. Press t (or click the chat box), type a note, press enter. It goes to the loop named on the box.
  2. Press +, finish the line /loop 1m run the tests again, press enter. That makes a loop, the way it will in the app.
  3. The web loop asks before it reads a site: the question is above the chat box. a, y or n answers it.
  4. Watch the debugging run move through its four steps (a real 43-second run of Qwen3.5 9B). A minute in, the tests turn green.
  5. m switches the model off: the loops wait. x starts over.

Also open in a Terminal window, where the tests and web pages run for real. Again: Loop board preview 2.command in docs/private/loops-preview/.

What changed since round one

  • Three new designs and a new timeline. Round one is kept: the first page.
  • The chat box is in every design, and under a single run too (enter). A note goes to the loop named on the box. /loop … typed there makes a loop.
  • Diagrams. Every loop now has its four steps drawn: as bars in the Tree, as a list in Focus, as boxes with arrows in the Timeline.
  • One place for questions. A loop that needs you asks above the chat box, and a y n answer it from anywhere.
  • A status line like the one on /agents: loops, running, needs you, in line, model.

What a note does

  • A run is under way: the note is sent to that run. The model reads it when its turn ends, as a message typed in a busy window does today.
  • Between runs: the loop’s next run starts with your note on top of its message.
  • In this preview the debugging run is a recording, so it goes on as it went. The board says so where the note lands.

Real

  • The debugging run. Qwen3.5 9B on this Mac, run by the app itself (coding -p), today at 11:57, 43 seconds. Its steps and closing words are its own. The four steps in the diagrams follow the lines it wrote.
  • The tests. Five real tests of a small sample project. The Terminal window runs them again each time. This page uses the recorded results of those runs.
  • The web pages. Bun’s and Ollama’s release pages on github.com. The Terminal window reads them each time. This page shows what they answered at 13:15: Bun 1.4.2 (2026-09-05), Ollama 0.35.1 (2026-10-02).
  • The drawing and the keys. One piece of code, used by the Terminal window and by this page.

Not real

  • No model runs now. The summary lines of the test loop and the web loop are the preview’s own wording, made from the real results.
  • There is no /loop in the app yet. The window’s name and ~/Desktop/trades-export are a sample.
  • A loop made here is a test loop, or a web loop when its message speaks of pages. A debugging loop cannot be started: one was recorded.
