What version 2 adds

  • A bigger ring with a hub. 9 rows instead of 5. The comet still goes round while it works; the middle of the ring now shows the step, the try, a bar for the step's progress and its time.
  • The stage track. The six stages with each one's time, and a bar for the whole run with the steps done and an estimate of the time left.
  • NOW. The step, what it is doing, the command, the file and function it is in, what it proves, the doubt review, the model's speed and memory, and the rewind points.
  • Guards. The stop list as meters: diff size of 100 lines, files of 3, tries of 3, and a mark for the tolerance, packages, deletions or secrets, and the poster's list. The guard that trips turns amber while it asks you.
  • Tasks. The plan as a table: each task's check, tries, diff, doubt result and time. In other stages the same place lists the questions, parts, checks, review areas or reviewers.
  • Math check. Newton's residual per step for each try, with the tolerance line, and the numbers each task proves. On the coding run it is the backoff waits against the 30 s cap.
  • Output and diff. The command's output appears as it runs; the diff is written line by line as the model edits.
  • Timeline. Every step with its time and stage, and the gauges from the remote footer you picked (speed, context, GPU) at the bottom.

Made faster

  • Only the lines that change are drawn again. Between ticks that is the ring, the NOW panel, the meters and the newest output line, about 15 of 59. This page does it line by line; the app would turn on Ink 7's incrementalRendering, which does the same.
  • Every panel has a fixed height, so nothing moves when a line is added: output, diff and timeline keep their newest lines, and the task list scrolls to keep the current task in view.
  • Long text is cut with "…", never wrapped, so a long command or path cannot push the layout down.
  • It fits by itself, in your order. The ring with NOW and the tasks with the math check always stay. As rows run out, the blank rows and dividers go first, then the timeline, output and diff shrink, then the guards go to one row, then the timeline goes, then output and diff, then the guards. The ring drops to 5 rows only when even that is not enough, and below 100 columns the table drops its time, doubt and diff columns. A stop box takes its rows from the same end.
  • The comet and spinner run at 12 frames a second here; the app would cap the /agents view lower, about 8, which is enough for the comet and costs less on a remote connection.

Your answers, as this preview shows them

  • 112 × 59 only while /agents runs. Before it, the window is yours (Your window); it grows as /agents opens and goes back when the run ends. A window already wider or taller keeps that side: 150 × 55 grows to 150 × 59.
  • The largest that fits. The font stays; the window takes what the screen fits (Screen fits), and the view lays itself out for that.
  • Kept at quit. Quitting in the middle of a run leaves the window as it is; only the end of a run gives your size back.
  • The whole window, esc to the chat. While it runs, esc shows the chat with one live line, at the big size. Once it has finished, esc closes /agents and the window goes back; /agents opens the run again.
  • What always stays: the ring with NOW, and the tasks with the math check, down to 80 × 24.
