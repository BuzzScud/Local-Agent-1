Does thinking help Gemma? · the 28-task test, step by step

version 4
Before you start

Open Terminal next to this page

You’ll run the same 28 practice tasks twice, once with Gemma’s thinking off and once with thinking on, and this page will tell you which did better. Each step shows exactly what to type and what Terminal should print back. It takes about 2 hours, mostly waiting.

Do these three things first
  1. Open Terminal: press ⌘ Space, type Terminal, press Return. Put it beside this window.
  2. Quit Agentic Coder: type /exit in every Agentic Coder window, or quit the app. Wait for any Claude session that’s testing Gemma to finish.
  3. Plug in the Mac and close apps you don’t need (browsers with lots of tabs, the desk servers). Gemma needs about 8 GB of memory.
How each step works: press the blue Copy button, click in Terminal, press ⌘ V, then press Return. Compare what Terminal prints with the dark box underneath. If it matches, press the big button at the bottom right. If it doesn’t, press Something’s different.
Step 1 of 7 a few seconds

Free the model

Only one copy of Gemma fits on this Mac. The app keeps its copy loaded for 30 minutes after you close it, and right now that copy runs at 16k instead of 32k. This unloads it.

1Type this into Terminal
%coding stop
2Terminal should print one of these · either is fine
Stopped the model on port 17600; its memory is free. — or — No model is loaded.

If it printed something else

“Still in use by an open Agentic Coder window”
An Agentic Coder window is still open. Type /exit in it (or quit the app), then run the command again.
“command not found: coding”
Type this instead: ~/.local/bin/coding stop
Step 2 of 7 about 10 seconds

Make a test copy of the app

A copy nobody else edits, so a Claude session changing the app can’t change the test halfway through. It also makes the gemma-28-tests folder on your Desktop, where the results will go.

1Type this into Terminal · it’s one long line; Copy takes all of it
%rsync -a --delete --exclude '.git' --exclude 'models/*/results' --exclude 'agentic-coder DOCS' --exclude 'backups' --exclude 'dist' --exclude 'Agentic Coder.app' ~/Desktop/agentic-coder/ ~/worktrees/gemma-test-copy/ && mkdir -p ~/Desktop/gemma-28-tests && echo "copy ready"
2Terminal should print
copy ready

If it printed something else

“No such file or directory” about ~/Desktop/agentic-coder
The app’s folder has moved. Stop here and tell Claude where it is now.
Nothing at all yet
Wait a few seconds. The copy is about 63 MB.
Step 3 of 7 a few seconds

Check there’s room for Gemma

Gemma needs about 8 GB of free memory. With less, the test still runs, but slowly, and the timings stop being fair.

1Type this into Terminal
%cd ~/worktrees/gemma-test-copy && node -e "import('./models/index.mjs').then(m=>console.log((m.availableBytes()/1e9).toFixed(1)+' GB free (the test needs about 8)'))"
2Terminal should print a number · yours will differ
9.4 GB free (the test needs about 8)

The number is only an example. You want 8 or more.

Under 8 GB

Free some memory
Quit apps you don’t need: browsers with lots of tabs, the desk servers, Agentic Coder. Wait 10 seconds, then press Copy again and rerun the command.
Still under 8
You can go on above about 6 GB. The test will be slower. Below 6, stop and try again later.
Step 4 of 7 1–5 minutes

Quick check: one task with thinking on

Gemma hasn’t been run with thinking on in this harness before. Five minutes now makes sure it thinks, stops and acts, before you spend an hour on it.

1Type this into Terminal
%cd ~/worktrees/gemma-test-copy && caffeinate -i node models/evals/bench/run.mjs --model gemma --think on --only 10 --out ~/Desktop/gemma-28-tests/check 2>&1 | tee ~/Desktop/gemma-28-tests/check.log
2Terminal should print lines like these · from this morning’s run of the same task
server up on http://127.0.0.1:17600, ctx 32768, thinking budget 2048 · Plan() ✗ Bash(npm test) · Read(pages.mjs) · Ask(Before I change anything: change pages.mjs (+1 −1)) · Update(pages.mjs) · Bash(npm test) PASS think=on 10-fix-off-by-one 28s 6 steps 1 errors thinking on : 1/1 passed, 28s total saved ~/Desktop/gemma-28-tests/check/summary.json

The ✗ on the first test run is normal: the tests fail on purpose until the bug is fixed. With thinking off this took 28 s; with thinking on it will take longer.

Step 5 of 7 about 30 minutes

The 28 tasks, thinking off

The “before” picture: Gemma as it runs today. Leave the Mac alone and don’t use Agentic Coder while it runs, because it would share the model.

1Type this into Terminal
%cd ~/worktrees/gemma-test-copy && caffeinate -i node models/evals/bench/run.mjs --model gemma --think off --out ~/Desktop/gemma-28-tests/off 2>&1 | tee ~/Desktop/gemma-28-tests/off.log
2Terminal should print one PASS or FAIL line per task · this morning’s real lines, then how it ends
server up on http://127.0.0.1:17600, ctx 32768, thinking budget 2048 · Plan() · Read(export.mjs) · Test(export.test.mjs) … FAIL think=off 1-json-flag 370s 6 steps 0 errors --json output wrong PASS think=off 10-fix-off-by-one 28s 6 steps 1 errors PASS think=off 11-fix-sort-text 11s 6 steps 1 errors … 25 more tasks … thinking off: NN/28 passed, NNNNs total saved ~/Desktop/gemma-28-tests/off/summary.json

The tasks run in text order (1, 10, 11 … 19, 2, 20 … 28, 3 … 9), so don’t worry that 2 comes after 19. FAIL lines are fine. They’re the results. You only need to wait for the …/28 passed line.

If it stopped before the “/28 passed” line

You pressed Control-C, or the Mac slept
Go back to step 1 and run the steps again. The tasks that finished are in off.log, and step 7 can read a half-finished log too.
An error message instead of PASS/FAIL lines
Stop and tell Claude “the thinking-off run errored”. It will read off.log.
One task sits for a long time
Leave it. After 15 minutes the runner marks that task FAIL and moves on.

How to read the answer (decided before the test, so it can’t be argued afterwards)
  • on passes 2+ more thinking helps, so use High for real work.
  • within 1 could be luck with one run each, so keep Low (it’s faster).
  • on passes fewer keep Low.
What this test can’t tell you: whether 64k of memory helps. These tasks never use more than about 2,500 tokens, so that needs a long job like the chart bug. That’s a separate test.
