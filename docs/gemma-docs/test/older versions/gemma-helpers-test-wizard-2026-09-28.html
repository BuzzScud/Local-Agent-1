Do the helpers make Gemma faster? · the before/after test, step by step

version 1
Before you start

Open Terminal next to this page

You’ll run the same 5 practice tasks with the new helpers off and then on, both the way the app normally works and step by step. This page then tells you whether Gemma got faster. Each step shows exactly what to type and what Terminal should print. About 2 hours, mostly waiting.

Do these three things first
  1. Open Terminal: press ⌘ Space, type Terminal, press Return. Put it beside this window.
  2. Quit Agentic Coder: type /exit in every Agentic Coder window. Wait for any Claude session that’s testing Gemma to finish: only one Gemma fits on this Mac.
  3. Plug in the Mac and close apps you don’t need. Gemma needs about 8 GB of memory.
How each step works: press the blue Copy button, click in Terminal, press ⌘ V, then press Return. Compare what Terminal prints with the dark box underneath. If it matches, press the big button at the bottom right. If it doesn’t, press Something’s different.
Your coding app is not changed. Everything here runs from the test copy in ~/worktrees/agentic-helpers. Nothing is committed yet.
Step 1 of 7 a few seconds

Free the model

Only one copy of Gemma fits on this Mac. The app keeps its copy loaded for 30 minutes after you close it. This unloads it.

1Type this into Terminal
%coding stop
2Terminal should print one of these · either is fine
Stopped the model on port 17600; its memory is free. — or — No model is loaded.

If it printed something else

“Still in use by an open Agentic Coder window”
An Agentic Coder window is still open. Type /exit in it, then run the command again.
“command not found: coding”
Type this instead: ~/.local/bin/coding stop

It asks whether to work in another project
Pick “No, stay”. It is working in the copy on your Desktop.

How to read the answer (decided before the test, so it can’t be argued afterwards)
  • better less time and no more of Gemma’s calls in all, no task that passed before fails now, and the notes page no more than 10% slower.
  • mixed some of that, not all. The table shows which task went the other way.
  • no not faster and not fewer calls, or two or more tasks that passed now fail.
What this test can’t tell you: with one run of each task, a difference under about 10% can be luck. And the code search helps most in a big project you use every day. The practice projects are small, so this test undersells it.
