  • Free memory at the start: 6.9 GB. The check's estimate for 128k: 7.1 GB. The most it really took: 4.6 GB.
  • The earlier 128k memory test (short prompts, 8.7 GB free at its start) peaked at 10.0 GB for Gemma and took 6.5 GB from free memory. This run peaked at 9.9 GB for Gemma, the same, but took only 4.6 GB from free memory, most likely because the Mac moved some other programs' memory to swap instead (swap peaked at 1.21 GB). Gemma's own size is the steady number; "from free" depends on what else is open.
  • Swap first showed up 4 min 03 s in, at 1.21 GB. The Mac made room by moving other programs' idle memory to swap while pressure stayed "fine". What caused it is not proven: it can be this test, or other programs open at the time (another Claude session was starting a test of its own).

The follow-up question

After the answers, a short question went to the same slot: "Which of your answers was the release codename?" It reused 102,713 tokens already read and processed only 59 new ones, in 3 s. So a long conversation does not get read again on every turn. Its answer: harbor-lantern.

What this does and does not show

  • It shows that at 128k one slot can hold 102,620 tokens on this Mac, and how fast Gemma reads and writes at that depth.
  • It does not show reasoning across 100k tokens. Finding a planted line is the easy kind of test; a question that needs two distant parts of the text together was not asked.
  • One slot only. The second slot shares the same memory pool, so two slots each holding 50k would use about the same memory but were not run.
  • The text is source code. Prose may behave differently.
  • The model file was already in the Mac's memory (a cold start is a separate test).
