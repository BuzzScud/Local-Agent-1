Where does a long task’s time go? · Gemma vs Qwen, step by step

version 1
Before you start

Open Terminal next to this page

You’ll give Gemma and then Qwen the same long question, one that makes them read a lot of code. The test times every step: reading, thinking, writing, and re-reading what they already read. It also notes each time memory fills up and whether they read the same file twice. At the end you build a report page that answers “is step 3 good enough?” It takes about 45 minutes, mostly waiting.

Do these four things first
  1. Open Terminal: press ⌘ Space, type Terminal, press Return. Put it beside this window.
  2. Quit Agentic Coder: type /exit in every Agentic Coder window, or quit the app.
  3. Don’t start a Battle while this runs. Only one model fits in memory, and a second one would crash.
  4. Plug in the Mac. Each run keeps the Mac awake by itself until it ends.
How each step works: press the blue Copy button, click in Terminal, press ⌘ V, then press Return. Compare what Terminal prints with the dark box underneath. If it matches, press the big button at the bottom right. If it doesn’t, press Something’s different.

Nobody has run this test yet, so steps 2 and 3 show the lines the test prints with the times and counts left for you to find out (in yellow). Steps 1 and 4 show exactly what you’ll see.

Step 1 of 4 a few seconds

Free the memory

After you quit Agentic Coder it keeps its model loaded for 30 more minutes, in case you come back. This unloads it now, so the test has the memory to itself.

1Type this into Terminal
%coding stop
2Terminal should print one of these · either is fine
Stopped the model on port 17600; its memory is free. — or — No model is loaded.

If it printed something else · press “Show what it should print” to see the expected lines again

“Still in use by an open Agentic Coder window … Quit that window first.”
An Agentic Coder window is still open. Type /exit in it (or quit the app), then run the command again.
“command not found: coding”
Type this instead: ~/.local/bin/coding stop

Step 4 of 4 a few seconds

Build the report and open it

This reads the two runs you just made and writes one page in gemma-docs → test, then opens it in your browser. It has five tabs: Verdict, Why long tasks get slow, When memory fills, Step by step, and How it was measured. Keys 1–5 switch tabs.

1Type this into Terminal
%cd ~/Desktop/agentic-coder && node models/evals/tools/long-task-page.mjs && open ~/Desktop/gemma-docs/test/gemma-vs-qwen-long-task-2026-09-29.html
2Terminal should print this, and the page opens
wrote ~/Desktop/gemma-docs/test/gemma-vs-qwen-long-task-2026-09-29.html (gemma: N steps, N s; qwen: N steps, N s)

If it printed something else · press “Show what it should print” to see the expected lines again

“no long-task runs yet”
Neither run saved its results. Check that steps 2 and 3 each ended with a saved line.
Only “gemma: …” or only “qwen: …”
One run is missing. The page shows the one it has. Run the missing step, then this step again, and the page updates.
You ran a step twice
That’s fine. The report uses the newest run of each model.

How to read the answer (decided before the test, so it can’t be argued afterwards)
  • Reading again under 10%Re-reading isn’t where the time goes. The way memory is trimmed is fine as it is.
  • Reading again 10% or moreWorth fixing: the notes and trims waste time. That becomes the next change.
  • Read a part again after its notes“Forgets what it read” is real. First fix to try: a lower thinking cap (4,096), so memory counts as full later.
  • Writes 25%+ slower at the endLong tasks slow down mainly because memory fills. A leaner memory helps more than a faster runtime.
What this test can’t tell you: whether the answers are right. It times one long question per model, once each, so it shows where the time goes, not which model is smarter. That’s what the Battle tab is for.
