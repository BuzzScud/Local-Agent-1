How to get Gemma doing the harder tasks

Short answer: more "look around" helpers won't do it. Checkers will: the app proves what "done" means before Gemma writes code, then tests every draft against that. That one change took the hardest bug from 0 wins to 3 of 3. The other thing missing: Gemma has never been tried on a hard task, so that comes first.

Look-only helpersA second copy of the model searched and reviewed for the main one (the Fable-style round). They found the right spot once, but cost 8–9 minutes and fixed nothing.No gain

Where Gemma slipped today

Bent the testIn practice task 1 it wrote a weak test, then hard-coded the answer to pass it. The app still went ahead to "try changes" even though no draft passed the test it chose.Needs a fix
Got stuck re-readingIn practice task 14 it rewrote the wrong function, then kept reading the same file.Needs a guard
Ran out of roomAt 16k, the setup alone took 41% of its memory before it wrote a word. The notes-page run filled up and threw its draft away.Use 32k
Saved with no file nameIt wrote the whole page twice without saying where to save it. The app now keeps the page when that happens.Fixed

Does it need helpers? Not the kind that is a second model looking around. Your Mac holds one model at a time, running two at once made both slower, and the test showed no gain.

It needs the kind that isn't a model at all: tests, a browser check and a strict grader the app runs itself. A 12B model is good at small fixes that can be checked. It is weak at long hunts on its own. So the app should turn big jobs into small jobs it can check.

The plan, in order

1Measure first. Run Gemma on the chart bug (3 tries, ~15 min) and finish the practice tasks (~40 min). That shows whether it is already close.No code
2A grader it can't bend. If no draft passes the test Gemma wrote, stop and write a new test. Don't go ahead to "try changes". Reject a test that only checks one hard-coded case.Small
3Room to work. Run at 32k by default. It fits: about 7.6 GB. Also make the setup text shorter so less memory is used before it starts.Small
4More checks first. Check first worked on one bug in one project. Add checks for "the page is cut off", "the text overlaps" and "the number is wrong", and try them on other bugs.Medium
5Break big jobs into small ones. For a change across several layers: write the plan, change one file, check it, then move to the next file. Each step should be something a 12B model can pass.Medium
6Search before reading. The search model is already loaded for memory. Let it rank which files matter before Gemma opens any, since reading was 84% of the time.Medium
7Speed helper for Gemma. Only once 1–6 work. It makes Gemma faster, not smarter.Later

What to expect

Within reach Likely

Explaining files, one-file pages, small bug fixes, and bugs the app can check in a browser. The chart bug is here once check first runs.

Out of reach for now Unlikely

Long open hunts with no check, honest claim checks on real data, and changes across front end, server and tests at once, unless the app breaks them into steps.
