Inside step 3: the shortcut, for fix and change

Gemma never edits your files. It writes tests and drafts, and the harness keeps only what passes.

  1. Gemma writes a test that should fail today and pass once the work is done. For a fix, the project’s own failing test does this job.
  2. Gemma drafts two versions of the change.
  3. The harness picks the test the drafts agree with. If no draft passes it, it can’t tell yet whether the test or the drafts are wrong.
  4. Gemma tries changes until one passes that test: up to 8 tries, each checked by the harness.
  5. You OK it. “Before I change anything: change pages.mjs (+1 −1). Go ahead?”
  6. The harness writes the change and runs the tests again.

If the shortcut can’t find a good test, it says so and switches to step by step, on the right.

Inside step 3: step by step, for everything else

Gemma asks for one tool at a time. The harness decides whether it runs.

Gemma picks one toolRead, List, Search, Edit, Write, Bash, a to-do list, or a question to you.
3 safety gatesBlocked words (rm -rf, sudo, git push). Your OK. A fence that keeps commands inside the project.
The harness runs itand hands the result back to Gemma.

Round and round, up to 40 steps. It ends when Gemma answers instead of asking for a tool. It stops itself if it repeats the same step or hits 5 errors in a row.
