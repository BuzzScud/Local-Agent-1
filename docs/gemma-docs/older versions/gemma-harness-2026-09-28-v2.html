Inside step 3: the shortcut, for fix and change

Gemma never edits your files. It writes tests and drafts, and the harness keeps only what passes.

  1. Gemma writes a test that should fail today and pass once the work is done. For a fix, the project’s own failing test does this job.
  2. Gemma drafts two versions of the change.
  3. The harness picks the test the drafts agree with. If no draft passes it, it can’t tell yet whether the test or the drafts are wrong.
  4. Gemma tries changes until one passes that test: up to 8 tries, each checked by the harness.
  5. You OK it. “Before I change anything: change pages.mjs (+1 −1). Go ahead?”
  6. The harness writes the change and runs the tests again.

If the shortcut can’t find a good test, it says so and switches to step by step, on the right.

Inside step 3: step by step, for everything else

Gemma asks for one tool at a time. The harness decides whether it runs.

Gemma picks one toolRead, List, Search, Edit, Write, Bash, a to-do list, or a question to you.
3 safety gatesBlocked words (rm -rf, sudo, git push). Your OK. A fence that keeps commands inside the project.
The harness runs itand hands the result back to Gemma.

Round and round, up to 40 steps. It ends when Gemma answers instead of asking for a tool. It stops itself if it repeats the same step or hits 5 errors in a row.

Making the Gemma harness more like Opus 5.5

Gemma’s harness already has the same core loop as Opus 5.5: the brain asks for one tool, the harness checks it and runs it, and the loop ends when the brain answers. What it lacks is Opus’s grading. Opus is marked by tests it never saw, and every test is run 5 times. Gemma writes the test it gets marked by, and it has been run once, on 9 tasks. Four ideas are worth copying. Four don’t fit a 16 GB Mac.

One thing to know first: most of the Opus 5.5 picture shows how Anthropic tests a model (hidden tests, 5 runs, teams of 100). It isn’t a guide to how Claude Code works day to day, so the useful part is copying its testing discipline.

The four worth copying, in order

Do #1 first. Without a fair score, there’s no way to tell whether #2–#4 helped.

1

Score it the way Opus is scored

Opus: every test run 5 times, score = the average.

  • What: run all 28 practice tasks 5 times each, on Gemma exactly as it is today. Then add the 28 real requests and the chart bug.
  • Why: 9 tasks, run once, can’t tell a real difference from luck. This becomes the “before” picture for every change below.
  • Cost: about 3 hours of the Mac, no code changes. The test runner can already repeat each task 5 times.
2

A grader Gemma can’t bend

Opus: hidden tests it never saw. It can’t peek at them.

  • What: three guards in the harness. a. If none of Gemma’s drafts pass its own test, stop trusting the test: switch to step by step, or ask you. Don’t keep trying until something passes. b. Refuse a change that copies the test’s expected answers into the program. c. After a change, check that nothing already in the file disappeared unless you asked for it.
  • Why: this would have caught both of today’s failures. (a) and (b) catch the --json task, where Gemma hard-coded 2 trades to pass its own wrong test. (c) catches the perimeter task, where area() was deleted.
  • Cost: harness code only, so it helps any brain, including the next one.
3

Turn thinking up

Opus: thinking at the top setting.

  • What: give Gemma a “High” level that switches its thinking on. The switch already worked in this morning’s live check. Test it two ways: on for every step, and on only while it writes the test (the step that went wrong).
  • Cost: slower. Each step can think for up to 2,048 tokens, about 2½ minutes at Gemma’s writing speed.
  • Watch: High didn’t help the 27B on the chart bug. That was a different brain, so measure before trusting it either way.
4

More room to remember

Opus: up to 1 million tokens.

  • What: run Gemma at 64k instead of 32k. That’s already a start option (--ctx 64k), and the settings card can make it the default.
  • Why: each token costs Gemma a quarter of the memory it cost the 27B. 64k needs 7.8 GB and 128k needs 8.4 GB, both less than the 27B’s 11.9 GB at 32k. Fewer trims means fewer slow re-reads.
  • Watch: when the memory is trimmed, Gemma has to re-read what’s left. A full re-read of 64k takes about 8½ minutes, roughly what the 27B paid at 32k. Gemma’s reading speed has only been measured on short prompts.

Not worth copying on this Mac

Teams of agents

Measured 25 Sep: two answers at once on this Mac are slower in total than one (6.4 tokens a second in total, against 8.05 for one). On 27 Sep the 27B got helpers, and they made no difference: 0 fixes on the chart bug, and the brain never asked for a helper.

A backup model

A second brain won’t fit in 16 GB beside Gemma, and the 27B is being removed to free disk space. On 27 Sep, a fresh copy of the same brain as a rescuer cost 8–9 minutes a try and never found the cause.

Watchers on every turn

They would need a second model reading every step. On your own Mac, the blocked words, your OK and the fence already cover the risk.

1 million tokens

Gemma’s limit is 256k. Re-reading that much would take over half an hour, so 64k is where the extra room pays off.
