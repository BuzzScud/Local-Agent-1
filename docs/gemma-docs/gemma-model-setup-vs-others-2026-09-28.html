The basic structure: five parts

Every local model setup has the same five parts, whatever the tool. Ollama, LM Studio and plain llama.cpp all do. So does ours: nothing is missing.

1
Model fileThe weights: billions of numbers in one file.
2
EngineDoes the math on the Mac's graphics chip.
3
ServerKeeps it loaded and answers requests.
4
Chat rulesHow messages are written for it, and how it picks words.
5
Your appSends messages, gets words back. Not part of this check.

Below, each part is split into its pieces and put side by side: the common way (Ollama) on the left, ours on the right.

The two things we looked at

Both were done on 28 Sep, after your picks.

The engine Tested, kept

Was
A special build of llama.cpp made for Bonsai, 625 changes behind the official one.
Done
Built the official llama.cpp v0.5.0 beside it and ran the same speed test on both, with the app's settings.
Result
The same speed plain, and Prism's build 5% faster with Gemma's speed helpers (16.7 vs 15.9 words/s), at the same memory. Tool calls and thinking worked on both. So Gemma stays on Prism's build; the official one stays on the Mac, and AGENTIC_ENGINE=official switches to it. The results are on the engine speed test page in test/.

Memory size Done

Was
Set by hand to 262,144 tokens. It was checked only at startup, and then only warned.
Done
Now 64k, about 8.9 GB (9.8 GB with the speed helper). It's checked at every start and restart, and in coding -p.
Now
  • It doesn't fit: it starts at 64k anyway, and one line names the apps using the most memory (your pick).
  • Another Gemma is loaded (a test run, a speed test): it says which and waits, then starts by itself; esc starts anyway.
  • Left loaded at another size: restarted at 64k when no other window is using it.
