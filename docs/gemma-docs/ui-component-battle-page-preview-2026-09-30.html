How it was run

  • Gemma 4 12B QAT, thinking on at High · Qwen3.5 9B, thinking on at High. One model at a time, each request in an empty folder, the way coding -p runs it, with the tests’ settings (32k of memory unless the Tests page’s panel changed it).
  • Part 1 · Card pick needs no model: the app’s own code says whether a request is a page request and which cards go along.
  • Part 2 · Folder on: the cards of every set and the layout check, which sends what it finds back to the model once. Part 3 · Folder off: neither.
  • Every page was then measured the same way, whichever part made it: opened in headless Chrome at 1440×900, on a 390-wide phone and in dark mode, and checked for sideways scroll, text that overlaps, runs out of its box or is too faint, script errors, and a missing charset or viewport line.   • The rules, written before the first run: a page passes when one was made and the layout check finds nothing; the folder is working on a model when there is a fitting card for every request, carried on every folder-on run, and no more layout problems with the folder on; the battle gives a point for a clean folder-on page and a point for your vote.

The requests, word for word

1 · Data metric card

Build a single self-contained HTML file for a modern data card that a dashboard could drop in anywhere. The card should show a title, one large primary number, a short label, a small percentage change with an up or down indicator, and a thin sparkline or progress bar. Use only inline CSS and a tiny bit of JavaScript so the file works when opened locally with no build step and no extra assets. Make the layout clean, slightly rounded, and readable on both desktop and phone. Keep the whole thing under one file and ready to copy-paste.

5 · Notification card

Write a self-contained HTML file for an in-app notification card. Show an app icon or colored badge, a title, two lines of body text, a timestamp, and two small actions such as Dismiss and View. Style it with CSS in the same file and add light JavaScript only if a close button needs to hide the card. It should look like a modern product toast or inbox item and stay readable on a phone. No external libraries or extra files.

7 · Mini media player

Create a self-contained HTML file for a compact media player card. Show album art as a colored block or CSS shape, track title, artist name, a progress bar, and play, skip, and like buttons. Use only HTML, CSS, and a small amount of JavaScript to toggle play state and move the progress bar. The file must work when opened locally with no audio file required. Keep the look clean and app-like so it could live in a sidebar or mobile sheet.
