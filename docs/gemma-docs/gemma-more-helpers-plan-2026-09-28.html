More helpers for Gemma: the plan

You asked for helpers that make Gemma right more often, across all four kinds of work: fixing bugs, building new pages or apps, changing features across files, and explaining code. They could be programs and checks, plus small add-on models of 1 GB at most. So there are no extra Gemma calls and nothing goes online. Below are 8 helpers, best first. Each one fills a gap that is still open today. Nothing is built yet. Your app and the repo are unchanged.

The helpers, best first

A check that passes costs Gemma nothing. A check that fails goes back to Gemma as one message, the same way failing tests do today, so it only costs a step when something is actually wrong.

1

Try it: run new pages and scripts

The gap: a page Gemma writes is never opened, and a new script is never run. The notes.html run is the example.

After Gemma makes or changes a page, the program opens it in a hidden browser. It collects console errors and files that fail to load, and clicks each button once. A new script runs once in the throwaway copy. Whatever breaks goes back to Gemma.

Names check

The gap: a wrong import, a misspelled function or a missing export parses fine, then breaks when it runs.

After each edit, a checker looks for three mistakes that are always real: a name that isn't defined anywhere, an import of a file that doesn't exist, and an import of something the other file doesn't export. For JavaScript and TypeScript it uses TypeScript's own checker, filtered to those three. For Python it uses pyflakes.

Nothing lost

The gap: when Gemma rewrites a whole file, a function it never meant to touch can quietly disappear.

Before and after each rewrite, the program lists the file's functions and exports and compares the two lists. Anything that vanished without being asked for goes back to Gemma, and the change you approve shows a warning.

Answer check for explanations

The gap: when Gemma explains code, the files, functions and line numbers it names are never checked.

Every file and function name in the answer is looked up in the project, along with any line number it gives. Anything that doesn't exist is marked in the answer, for example "⚠ no function called loadRows in this project". The answer is marked, not rewritten, so no Gemma call is added.

Real library signatures

The gap: when Gemma uses an installed package, it writes the function names and options from memory. A small model often gets them slightly wrong.

When the code imports an installed package, the real signatures of the functions it uses come along. For JavaScript they're read from the package's own type files; for Python, from the installed module.

Error pointer

The gap: when a command fails with a stack trace, Gemma spends a whole step just opening the line the trace points at.

The lines each frame of the error points at are added to the error message, 5 lines on each side, before Gemma sees it.

7

Starter files for new pages

The gap: Gemma writes a whole new page in one long go. Writing is the slow part, and one bad write loses all of it.

For a "make a page" request, the program first writes a skeleton it knows is right: the file name you asked for, text encoding, phone sizing, light and dark mode, and an empty script. Gemma then fills it in with small edits.

8

Sharper finder (small add-on model)

The gap: finding the right code relies on one general-purpose matcher, bge-m3. It compares a summary of the request with a summary of the code, never the two side by side.

A reranker (bge-reranker-v2-m3) reads the request and each of the top 20 matches together, then puts them back in order. Picking the right file is the first thing every other helper depends on.

How we'd know it worked

The 28 practice tasks are mostly too easy for Gemma to show a difference (it passed 7 of 9 in the bake-off), and Gemma has never been tried on a hard task. So the first step is a hard set of 12 tasks, 3 for each kind of work:

  • Build new: the notes.html request plus 2 more pages or scripts, each with an automatic check.
  • Fix bugs: 3 real bugs from your apps, including the chart bug the old model couldn't fix (0 of 14) until the check-first path got it to 3 of 3.
  • Change across files: 3 changes that touch 2–4 files.
  • Explain: 3 questions with known answers, graded by the files and functions a right answer must name.
Win rule, set before anything runs: more of the 12 tasks passed with the new helpers on than with them off, no task that passed before fails after, and each task takes at most 15% longer. Every helper gets its own switch in /helpers, so any one that doesn't earn its place can be turned off.
