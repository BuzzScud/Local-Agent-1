Inside step 3: how the work gets done

Two ways, picked by the sorting step. Both are the same for Gemma and Qwen.

the model, the brain (writes the words and code)the harness (the code around it)you

The shortcut, for fix and change

The model never edits your files. It writes tests and drafts, and the harness keeps only what passes.

  1. The model writes a test that should fail today and pass once the work is done. For a fix, the project’s own failing test does this job.
  2. The model drafts two versions of the change.
  3. The harness picks the test the drafts agree with. If no draft passes any test, it stops trusting the tests and goes step by step.
  4. The model tries changes until one passes that test: up to 8 tries, each checked by the harness.
  5. You OK it. “Before I change anything: change convert.mjs (+1 −1). Go ahead?”
  6. The harness writes the change and runs the tests again. A change that removed something you didn’t ask to remove is sent back.

Step by step, for everything else

The model asks for one tool at a time. The harness decides whether it runs.

  1. The model picks one tool: Read, List, Search, Edit, Write, Bash, a to-do list, or a question to you.
  2. 3 safety gates. Blocked words (rm -rf, sudo, git push). Your OK. A fence that keeps commands inside the project.
  3. The harness runs it and hands the result back to the model.

Round and round, up to 40 steps. It ends when the model answers instead of asking for a tool. It stops itself if it repeats the same step or hits 5 errors in a row.

2 · It sorts

The harness decides which path the request takes. The model is a fallback here.

the model, the brain (writes the words and code)the harness (the code around it)you
