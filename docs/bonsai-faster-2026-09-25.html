Bonsai Code, faster: before and after

25 Sep 2026. Bonsai 2 27B on the M4 (16 GB), thinking off. Before: Prism's release of llama.cpp with n-gram guessing, as Bonsai ran it this morning. After: Prism's newest source with one routine of ours added, and a 1.1 GB helper model that guesses the next word for the 27B to check. The same Bonsai code on both sides. What it costs

More memory while Bonsai runs: the helper file (1.14 GB) and 0.5 GB more working space in this run (its working space, and one spare copy of the running state per slot to take a wrong guess back). The rule that picks the context counts 2.2 GB to be safe, so 32k now needs 11.92 GB free; below that Bonsai starts at 16k, as it already did when memory was short.

bonsai setup now builds the engine (about 3 minutes, needs cmake and Apple's command line tools) and downloads the helper (1.14 GB). BONSAI_HELPER=off runs without it.

How many guesses per check

The helper can guess several words ahead. More guesses help when they are right, as in code, and cost a longer check when they are wrong, as in prose. One guess was the only setting faster than before on all three kinds of writing, and it needs the least memory.

The engine change

test-backend-ops perf, MUL_MAT PQ2_0 x F32, m=17408 k=5120 (a feed-forward matrix), microseconds per run. Before: Prism's general small-batch routine for this format. After: kernel_mul_mv_pq2_0_multicol, which decodes each weight byte once and uses it for two words. 151 of 151 PQ2_0 MUL_MAT cases match the CPU reference (n = 1..8, Bonsai shapes, odd row tails).

The M4's GPU runs out of arithmetic before memory speed once more than one word is in flight, even for the engine's tuned 4-bit routine (Q4_0: 502, 1436 and 3087 µs for 1, 4 and 8 words). Prism's routine measured 932–1431 µs for 4 words and 1753–3096 µs for 8 across runs. Registers set the limit: 16 weights per thread or 4 words per pass ran out of them and got slower. the helper at the default -ub 512 needs 1.49 GB of working space and ran the GPU out of memory (10.9 GiB limit); -ub 128 needs 0.37 GB.

Notes

Task 1 is the one clear loss (91 → 146 s): it was the first task on the new engine, so Bonsai read its instructions once instead of restoring them (saved warm-ups are keyed by engine build), and its two drafts disagreed, which adds a round of tests and drafts. Task 21 took one wider fix either way and was 47 s slower on the same steps.

One run per side on the same Mac, one after the other; a second session was working in the repo at the same time, so both sides shared that load. Single-run task times vary by several seconds; the totals and the writing-speed probes are the steadier numbers.

The helper is DFlash2 (a block-diffusion drafter by z-lab / Inco AI), re-fitted by naklitechie to this ternary model's own hidden states, Apache 2.0. Prism merged DFlash2 support into their engine's source on 25 Sep, after the release Bonsai used.

With a guess the check runs two words through the model at once, so the result can differ from one-at-a-time writing where the model's top two choices were within rounding; Prism reports the same for their batched check.

The saved warm-up still restores with the helper on, and the helper kept guessing well afterwards (194 of 205 guesses accepted on the next code request (95%)). Saved warm-ups are now keyed by engine build, so the first start after the switch reads the instructions once (about 26 s).
