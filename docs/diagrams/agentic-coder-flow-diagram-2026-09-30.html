Agentic Coder: how it works

a coding agent in your terminal, running a model on this Mac · saved 30 Sep 2026

Two parts joined by one door

You type in a terminal. The terminal decides how to do the job and calls the model only when it has to. Every model in /model has its own box; one is loaded at a time.

The terminal never reads a model’s settings directly; it goes through one file, models/index.mjs. /update exits the app with code 75, and the launcher rebuilds and restarts it in the same window.

Step 2 in detail: where a request goes

Rules look at your words first. The model is asked only when no rule fits.

Under your request a dim line says where it went, for example Sorted as: change · shortcut. A rule change that moves any of the 101 test requests to another path fails the sort test.

The step-by-step loop

When no shortcut fits, the model works one tool at a time, and you approve each edit or command.

can call the modeltalks to the modelfalls back, repeats or comes backa number for each model, from your runs; bold = better

Built for small local models: one tool at a time, plain-text reads, edits that forgive small slips. Always blocked in every mode: rm -rf, sudo, git push, git reset --hard, git clean -f, kill, stopping services, piping the internet into a shell.

Focused paths: fixed recipes for common jobs

A recipe leaves the small model less to guess. Each lane says how every model did on it: tasks passed and the time they took.

Tries happen in a scratch copy of the project, not in your own files. The numbers: Prompt old vs new, 30 Sep: thinking on (High), 32k, 15 minutes a task at most, each task run once.

Memory: the model stays the same, what it knows changes

Facts about you and each project are saved after tasks, brought back when they fit, and scored by how the next task went.

Turn it off with "memory": false in settings.json, or stop only the auto-saving with AGENTIC_MEMORY_SAVE=off. /memory shows both memories; /memory undo takes the last save back.

The test bench: how a model gets graded

The same agent, run with no screen, on throwaway copies, then checked. Every model is graded the same way.

A new model is tested the same way: node models/evals/bench/run.mjs --model <id>. The numbers on this tab come from the newest test every model ran with the same settings.

Where things live

The code is in one repo; what the app builds and remembers is in two hidden folders in your home.

In the repo ~/Desktop/agentic-coder

agentic-coder/
├─ terminal/            part 1 · the agent you talk to
│  ├─ src/               cli · app (screen) · agent (loop) · flows · tools · ui · morning
│  ├─ test/  scripts/   unit tests, keys-in-a-real-terminal tests, report builders
│  └─ app/               Agentic Coder.app launcher, the coding script, icon
├─ models/              part 2 · the models and the bench
│  ├─ index.mjs          the one door
│  ├─ runtime/           llama-server, memory fit, warm-up, setup
│  ├─ gemma-4-12b/       Gemma 4 12B QAT · default
│  ├─ qwen3.5-9b/        Qwen3.5 9B · in use now
│  ├─ bonsai-2-27b/      retired, kept as a recipe
│  ├─ bge-m3/            finds memory facts by meaning
│  └─ evals/             the test bench
├─ cli docs/            every diagram, report and test page (mirrored to docs/)
└─ Agentic Coder.app     double-click: pick a folder, opens Terminal running coding

Model files are downloaded once with coding setup. Nothing here is sent anywhere: the model runs on this Mac. A model added to the list in models/ shows up on this tab by itself.
