What stands out

Most serious first. Each one comes from the measurements below; nothing here was changed.

1Worth fixing

The app logic has no tests of its own

13 files, 4,946 lines, are not imported by any test, not even through another file. They are the app's parts (keys, slash commands, settings panels, remote, model) that only the screen loads. Only the slower tests that drive the real app in a terminal reach them, and only the paths those tests happen to walk.

  1. app/app-panels.mjs829 lines
  2. app/app-keys.mjs795 lines
  3. app/app-slash.mjs786 lines
  4. app/app-run.mjs712 lines
  5. app/app-remote.mjs585 lines
  6. app/app-model.mjs442 lines

What would help: Move the decisions out of these parts into plain functions (as limits.mjs and perms.mjs already are) and test those directly.

2Worth fixing

Five functions of 560 to 790 lines

Each app part is one function that holds dozens of small handlers sharing one self. panelsPart alone defines more than 70 of them. A change anywhere in it means reading the whole function to know what else touches the same state.

  1. app-panels.mjs · panelsPart787 lines
  2. app-keys.mjs · keysPart764 lines
  3. app-slash.mjs · slashPart745 lines
  4. app-run.mjs · runPart680 lines
  5. app-remote.mjs · remotePart561 lines
  6. app-model.mjs · modelPart423 lines

What would help: Split by topic when one is next changed (in app-panels: web, MCP, hooks, rewind, effort): a smaller file each, same behaviour.

3Keep an eye on

The busiest files

agent.mjs changed in 115 commits in 15 days. tools.mjs is the biggest backend file (1,595 lines), is imported by 18 others and changed 55 times. commands.mjs and help.mjs change with nearly every new command.

  1. agent/agent.mjs115 changes
  2. app/commands.mjs67 changes
  3. app/help.mjs66 changes
  4. agent/tools.mjs55 changes
  5. headless.mjs32 changes
  6. app/weights.mjs32 changes

What would help: These are where conflicts between parallel sessions are most likely; keep their changes small and land them quickly.

4Keep an eye on

Logic files reach into the screen

12 imports go from backend files to screen files: for example app-keys.mjs → screen.jsx, and app-slash.mjs → start.jsx, rail.jsx, bot-layer.jsx. It ties the logic to Ink, so it cannot run or be tested without the screen.

  1. app/app-keys.mjs → app/screen.jsx
  2. app/app-keys.mjs → app/rail.jsx
  3. app/app-keys.mjs → app/home-looks.jsx
  4. app/app-model.mjs → app/screen.jsx
  5. app/favicon.mjs → app/start.jsx
  6. app/loops-draw.mjs → ui/theme.mjs

What would help: Pass what the logic needs from the screen in, instead of importing it.

5Keep an eye on

Many errors are dropped on purpose, and a few by habit

202 of 860 try blocks end in an empty catch {}. In sessions.mjs most are fine (removing a file that may be gone, writing to a closed window), but a failed save of the session record (noteFolder) is dropped without a word too.

  1. app/sessions.mjs31 empty catches
  2. app/door.mjs14 empty catches
  3. app/rewind.mjs12 empty catches
  4. flows/layoutcheck.mjs8 empty catches
  5. app/instructions-hub.mjs6 empty catches

What would help: Keep the empty ones for clean-ups; for saves, write one line to the log so a lost record can be traced.

6Keep an eye on

Two circular imports

claude-notes.mjs and claude-pack.mjs import each other, and so do tools.mjs and flows/localize.mjs. They work today, but load order decides whether a name is ready, which breaks in confusing ways after a move.

  1. agent/claude-notes.mjs ↔ agent/claude-pack.mjs
  2. agent/tools.mjs ↔ flows/localize.mjs

What would help: Move the few shared helpers (parseNote, resolvePath, didYouMean) to a small file both import.

7Keep an eye on

The code map is behind

docs/map was made on 4 Oct and still says agent.mjs has 3,784 lines and App.jsx 4,123. Since then both were split into parts: they are 612 and 1,041 lines now, and the new agent-*.mjs and app-*.mjs files are not described.

  1. agent/agent.mjs3,784 → 612 lines
  2. app/App.jsx4,123 → 1,041 lines

What would help: Run bun run codemap once; the agent starts from that map, so a stale one sends it to the wrong files.

How this was measured

  • A script read every .mjs file in terminal/src (the .jsx files and ui/ are the screen and were left out) and followed its import lines.
  • "Changes" comes from git log: each commit that touched the file, since the first one on 25 Sep 2026.
  • "Reached" follows imports from all 195 test files in terminal/test. Tests that start the real app in a terminal are not counted as reaching a file, since they load it as a program.
  • Function sizes count lines from a top-level function to its closing brace.
  • The test result is the last line of the test record (~/.agentic-coder/tests/record.jsonl).
