Agentic Coder Web · built and tested

8 Oct 2026 · in a worktree, not committed or pushed · checked on your real AI services and calculator, and on pretend ones in the tests
Built: a web page, a backend and a tools server for Agentic Coder, for many people at once. Every model request goes through one gateway to your AI services, and the calculator is a tool for the page, the API and the agent itself.

Two copies (your pick)

  • This Mac, Tailscale only: chat that runs Agentic Coder in each person's own folder, files, calculator, API keys, admin. coding web starts it; coding web on makes it start with the Mac.
  • Your AI server: chat + calculator only (Linux has no folder fence), in a container beside your calculator, behind https on a free sslip.io name. You install it with the step-by-step page.

What a person can do

  • Sign in with an account you made (invite link, once, 7 days).
  • Chat: each message is a real Agentic Coder run in their folder. Edits go through; every command asks Allow / Always / Deny in the browser; Stop works; a message typed while it works reaches it at its next step; the next message carries the conversation on.
  • Pick any of your models (Laguna q8 is admin only).
  • Files: see, upload (a .zip is unpacked), download one or all.
  • Calculator, with the two fixes. API keys for scripts, other apps and MCP.

Admin

Users (invite, reset link, make admin, delete, open their chats and files: your pick) · Queue (runs, requests at your AI, what each service has loaded and which is busy, live) · Usage (7 days: runs, requests, time on your AI, moved to the stand-in, Laguna) · Models (default model, the stand-in and its wait, allow or switch off each model) · Settings (limits, AI services, calculator and its login for formulas, page reading).

The rules on the way

  • Which model: the person's pick; your default when none.
  • AI 1 silent: no first word in 60 s plus the time to read what is sent (at the speed your service really reads, measured from its own numbers) → that request goes to the stand-in on AI 2, a line says so, and the run's next requests go straight there for 2 minutes. Laguna is never the stand-in.
  • Laguna q8: only after a yes. A message too big for the default model (about 100k tokens as loaded) asks: switch this run to Laguna, stay and read in parts, or stop. No answer in 30 min stops it. Admins may pick it by hand.
  • Your loaded models stay: a request can't unload one (keep_alive 0 is dropped), can't reload it at another size (its num_ctx is set to the loaded one), and one kept loaded for ever stays so.

A run, step by step

  1. The message waits its turn in the line (it says its place).
  2. The server writes that person's run home: your AI through the gateway with a one-time token, the calculator allowed, their folder trusted, no web reading unless you allow it.
  3. Agentic Coder runs as /loop runs do, in Accept edits, with a clean environment, no Screen tool.
  4. Each step streams to the page; a command waits for Allow.
  5. Its conversation is kept, so the next message carries on.

People kept apart

  • Each person has their own folder and their own Agentic Coder home (memory, settings, conversations). Nobody reads another's; an admin may read (your pick), never write.
  • A path that climbs out, a link out of the folder, or a .zip whose entries climb out is refused (tested with each guard taken away in turn).
  • A run's file tools refuse anything outside the folder: they do not ask, so nobody can click Allow on your files (Bypass is never used).
  • A run's commands are fenced by macOS: checked live, a fenced command could not read your saved keys in the Keychain (the same lookup outside the fence found them).
  • A run starts with a clean environment (your variables do not reach it), no Screen tool (a person elsewhere must not see this Mac's screen), no web reading unless you switch it on.

Signing in

  • Accounts only by invite (once, 7 days); the very first is a one-time setup link printed by the server.
  • Passwords: argon2id, 10 characters at least. Sign-ins, invites, resets and API keys are kept only as hashes.
  • 5 wrong tries a minute for a name from one address: sign-in waits a minute.
  • The cookie is HttpOnly, SameSite=Strict, and Secure behind https; any change made with it must come from the page itself.
  • A run's own token works only for the gateway and the tools, only from this Mac, and only while the run lives.
  • The calculator's password stays in the server's settings (mode 0600) and never reaches a page.
  • The repo is public: no address is written in the code; addresses live in the settings file.

Every model

What it can do (tools, think, pictures; "no tools"; "embeddings: can't chat"), how much it reads, its size, now (loaded, kept, busy, in use), who may pick it (everyone, admins, nobody), and Test · Load + keep · Let go on your real AI, each asking first. A change log at the bottom.

The rules it keeps

  • A model that cannot chat (an embedding model) can never take a chat job; one with no tools may, with a warning.
  • The stand-in and the last resort are never the same model; the last resort is never the Helper.
  • A model with a job cannot be switched off until the job has another model.
  • Let go is refused while that model is answering a request or a run.
  • A chat whose model was switched off or left the service goes on with the default, and says so.

The Helper in web runs

  • A web run's side jobs (summaries, the second look, Stays on task) go to the Helper through the gateway, to the Helper's own service.
  • It is the system's job, so it runs even when the run's person may not pick that model.
  • None set: the main model does them, as before. /loop's runs are unchanged.
