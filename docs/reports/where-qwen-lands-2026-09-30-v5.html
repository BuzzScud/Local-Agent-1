What Agentic Coder on your Mac changes

The middle Qwen column assumes a big GPU and a test setup built for each test. The right-hand column is the same model as you run it.

  • No screen controlAgentic Coder's tools read, write, run commands and search the web, but none of them moves a mouse.hits: Agent's Last Exam · OSWorld-2.0
  • Pictures and PDFs, no videoThe vision add-on reads pictures and PDFs (8 of 8 on the Vision check). Videos are not an input.hits: LVBench
  • 32k context settingYour settings give Qwen 32,768 tokens of context. The model can go to 262k, but a 16 GB Mac runs out of memory first.hits: GraphWalks · long coding jobs
  • 8,192 thinking tokensYour thinking limit is 8,192 tokens. For hard math, Qwen's own guide asks for room to write up to 81,920 tokens.hits: RiemannBench · science
  • ~16 tokens a secondQwen writes 15–18 tokens a second on the M4. Tests with a time limit (5 h, 10 h) get far fewer steps done.hits: Terminal-bench · DeepSWE
  • No plug-ins, no NVIDIA GPUMCP plug-ins are planned but not built, and PostTrainBench trains models on an H100.hits: AutomationBench · PostTrainBench

Why 24 of 24 here doesn't mean a high score there

Our practice tasks take a few minutes each and fit in one window of context. Google's tests run for hours (Agent's Last Exam gives 5 hours, PostTrainBench 10), over whole codebases, scored by strict checkers. Small models lose track over long jobs. That's the "D" on real coding work: the code looked finished and Qwen said "done", but it wasn't.

How to get a real number instead of a guess

Two of these tests are open and small enough to try: Terminal-Bench (runs in Docker, so it would need a harness that drives Agentic Coder) and Chartography-style chart questions through the vision add-on. Either one would turn a guess into a measurement. It would be a multi-hour run, and I haven't started one.

How each guess was made

  1. One real number. LVBench 70.0% is from Qwen's own model card for Qwen3.5-9B. No one has published a Qwen3.5 9B score on the other 18 tests.
  2. Best case = nearest real score × the gap on that kind of work. Long coding/terminal rows use the Terminal-Bench 2.0 gap (Qwen at about 1/5 of the top model). Computer-use rows start from Qwen's OSWorld-Verified 41.8%. Chart and video rows start from CharXiv 73.0% and LVBench 70.0%. Long-context rows start from AA-LCR 63.0%.
  3. Agentic Coder column = best case, cut for your setup. The biggest cuts are on rows that hit your 32k context (GraphWalks) and 8,192 thinking tokens (RiemannBench). Rows that need something the app doesn't have show "can't".
  4. The range in brackets is how wrong I could easily be. Treat the single number as the middle of that range, not a measurement.
  5. Same rules as Google's sheet: one try per task, highest thinking setting. Qwen's model card scores are at full precision. Your file is the Q5 version, which costs about a point.
A caution about the table itself: Google ran some tests itself and copied other models' numbers from their makers. So even the big four columns weren't all measured the same way.
