Model calls = calls to the brain before any work starts: the sort itself (inside a code project) or the “is this clear?” check. Your own lines were typed in your home folder, which is not a code project: the shortcuts are off there, so a line sorted as a change still goes step by step. For those lines the sort decides the quick reply, the question first and the dim line.

How it gets built

  1. A worktree of its own, from main as it is now. Main is not touched until you say so.
  2. The sort test first: the 101 lines with the path each must take. It fails on today’s code in 15 places.
  3. The rules: thanks and greetings, follow-ups, plain commands, pages, and the order of the clarity check.
  4. The dim line on screen, in both layouts.
  5. The pick list: the question call returns its answers; the question box shows them with “Something else”.
  6. Tests: the unit tests, then the screen driven for real (exit, the line, picking an answer).
  7. Real model: the 28 real requests, before and after, on the 27B.
  8. A results page in this folder, and a line in the test record for each run.

Limits you should know

  • The answers are guesses. The brain sees file names, not what is in them. It offered “Fix dark mode styling” in a project with no dark mode. “Something else” is always there.
  • In your home folder the gain is small. Your saved conversations show the brain already handled “ima need help” and “add it to my desktop” well there. The shortcuts, where a wrong sort costs most, only run inside code projects.
  • Short requests still get asked about. The brain called all 8 short requests unclear, “add a json flag” too. The plan does not change that: you chose “ask whenever unclear”.
  • Follow-ups are found by word rules. “what about the other one?” is missed and sorted as today. A line that names a file or code is never taken for a follow-up.
  • Not measured yet: seconds saved per request. The 12 → 2 is a count of calls, not a time.

Small picks I made for you

  • A command that names code stays with the brain, as today: “build a login page in Login.jsx”.
  • Set questions stay typed. “The tests pass today. What is wrong?” has no honest answers to offer.
  • No project map in the question. It cost 1.3 s more and gave the same answers.
  • The instructions Bonsai reads at start are not touched, so the next start is as fast as today.
